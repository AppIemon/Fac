# 참고 설계에서 배운 것

받은 `.litematic` 4개를 `tools/import_litematic.py` 로 뜯어서 분석한 기록.
원본은 `reference/` 에 그대로 두었다.

```bash
python3 tools/import_litematic.py reference/<파일>.litematic
```

| 파일 | 크기 | 블록 | DataVersion |
|---|---|---|---|
| `2.7万刷石机_稳定版` (조약돌 27k/h) | 5×7×5 | 101 | 4438 |
| `Bonemeal Farm 4k/h` | 13×12×13 | 773 | 4788 |
| `32 Furnace Array (Adil_Gamez)` | 6×11×24 | 553 | 4903 |
| `Unnamed` (켈프 팜) | 34×29×27 | 3,136 | 3953 |

---

## 1. 조약돌 27k/h — 물먹임 '나뭇잎'과 TNT

**구조**: Y=1 에 용암 3×3 코어, 그 둘레 12칸이 조약돌 생성칸.
Y=2~3 은 **물먹임 참나무 잎** 19개가 감싸고, Y=0 은 호퍼 12 + 상자 8.
Y=5 에 관측기·피스톤·**TNT·우는 흑요석**으로 만든 TNT 복제기.

**배운 것 1 — 물먹임 블록은 잎이 제일 싸다.**
나는 위키 튜토리얼대로 물먹임 *계단*을 썼는데, 효과는 같고 잎이 훨씬 싸다.
`cobblegen` 의 기본값을 잎으로 바꿨다 (`--water_block stairs` 로 계단도 가능).

**배운 것 2 — 내가 틀렸던 것.**
나는 "바닐라에 자동 블록 파괴기가 없어 채굴은 수동"이라고 단정했다.
**TNT 복제**가 그 역할을 한다. 시간당 27,000개는 손으로 캘 수 있는 수가 아니다.
다만 TNT 복제는 버그성 메커니즘이라 서버에서 막히는 경우가 있어,
이 저장소의 `cobblegen` 은 수동 채굴형으로 남겨 두었다. 필요하면 별도 설계로 추가할 것.

---

## 2. Bonemeal Farm 4k/h — 다층 베드 + 제자리 돌 재생성

**블록 구성**: 피스톤 79, 용암 42, 퇴비통 11, 호퍼 25, 관측기 28, 꿀 블록 5, 흑요석 11.

**배운 것 1 — 베드를 층으로 쌓는다.**
뼛가루의 확산 부피는 **7×11×7 로 세로가 11칸**이다. 나는 평평한 7×7 한 층만
썼는데, 층을 쌓으면 뼛가루 1개가 훨씬 많은 돌을 이끼로 바꾼다.

**배운 것 2 — 용암 42개는 제자리 돌 생성기다.**
이끼팜은 돌을 먹는다. 이 설계는 수확 후 빈 자리에 **돌을 다시 생성**해서
외부 돌 공급 없이 돈다. 내 설계는 돌을 손으로 채워야 한다.

**배운 것 3 — 피스톤이 가로로 민다.**
나는 "이끼 위에 피스톤을 두면 뼛가루 조건(위가 공기)이 깨진다"에서 막혔는데,
베드를 얇은 층으로 나누면 **옆에서** 밀 수 있다. 층마다 사방에 피스톤 링이 있다.

시간당 4,000개는 이 세 가지가 합쳐진 결과다. 내 `mossbed` 는 수동 괭이 수확
기준이라 여기까지 가지 못한다. 문서에 그 차이를 명시해 두었다.

## 3. 32 Furnace Array — 드로퍼 분배

**블록 구성**: 호퍼 110, **드로퍼 70**, 화로 32, 노트 블록 33, 중계기 21, 비교기 13.

**배운 것 — 호퍼 줄은 분배가 불균등하다.**
내 `smelter` 는 호퍼 라인 + 아래 방향 호퍼가 위 컨테이너에서 끌어가는 구조인데,
앞쪽 화로가 더 바쁘다(문서에 그렇게 적어 두었다). 이 설계는 **드로퍼 사슬**로
아이템을 밀어 균등 분배하고, 비교기로 각 화로의 재고를 읽는다.
화로 32대 규모에서는 드로퍼 방식이 정답이다.

## 4. Unnamed 34×29×27 — 켈프 연료 팜

**블록 구성**: 물 925, 켈프 125, 모래 125, 피스톤 125(전부 서향),
관측기 256, **드로퍼 128(위 방향)**, 화로 11, 가속 레일 26.

**배운 것 — 이게 내가 말한 '연료 구멍'의 답이다.**
직전 턴에서 매끄러운 돌 공장을 풀었더니 **석탄 250개/시간**이 공급원 없는
원료로 남았다. 이 설계는 켈프 125포기를 길러 화로 11대로 바로 말린다.
드로퍼 128개는 물기둥 바닥에서 화로까지 아이템을 올리는 엘리베이터다.

이걸 보고 `kelpfarm` 설계와 켈프 연료 라인 공정을 추가했다. 다만 내 설계는
**부력 수거**(물속에서 아이템이 떠오르는 성질)를 써서 드로퍼 엘리베이터 없이
천장 호퍼로 받는다 — 더 단순하고 블록이 훨씬 적다.

## 이 분석이 코드에 반영된 것

| 배운 것 | 반영 |
|---|---|
| 물먹임 잎 | `cobblegen` 기본값을 잎으로 (`water_block` 파라미터) |
| 켈프 연료 라인 | `kelpfarm` 설계 신규 + `kelp_farm`/`smelt_kelp_to_dried`/`craft_dried_kelp_block`/`burn_dried_kelp_block` 공정 |
| 연료는 되먹임 고리 | 솔버가 고리를 거부하지 않고 **고정점 반복으로 푼다** |
| 이끼팜도 고리 | 접어뒀던 순수지 공정을 진짜 고리로 교체 |
| 다층 베드 / 제자리 돌 생성 / 드로퍼 분배 | 아직 미반영. `mossbed`·`smelter` 문서에 한계로 명시 |

### 되먹임 고리 풀이

`engine/chain.py` 는 이제 고리를 정상으로 취급한다.
가동량을 소수로 두고 수요가 채워질 때까지 반복해서 키우는 고정점 방식이라,
**한 바퀴 순이익인 고리는 수렴하고 순손실인 고리는 발산으로 잡힌다.**

```
$ chain plan bone_meal --rate 100 --pick bone_meal=composter_vegetation_only
체인 오류: 고리가 발산한다 — 한 바퀴 돌 때 순손실이라 아무리 키워도 목표를 못 채운다.
```

초목만 퇴비화하면 뼛가루가 0.85개라 손해라는 사실이, 이제 계산에서 자동으로 나온다.
