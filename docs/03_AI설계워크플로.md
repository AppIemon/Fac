# AI 설계 워크플로 — "작동 원리만 알면 설계도가 나온다"

이 저장소의 목적은 **팜을 외우는 게 아니라, 원리를 입력하면 설계도가 나오게 하는 것**이다.

## 한 줄 요약

```bash
python3 -m engine.cli principle --json '{"source":"...","target":"...","process":"..."}'
```

이 한 줄이 → 아키타입 선택 → 치수 계산 → 층별 평면도 → 재료 목록 → 시공 순서 →
경고 → 점검표까지 만들어낸다.

---

## 1단계: 원리를 5칸으로 분해한다

유튜브 영상이든 설명이든, 팜을 보면 이 5칸만 채운다.

```json
{
  "source":    "무엇이 산출되는가",
  "transport": "어떻게 한 점에 모으는가",
  "process":   "어떻게 처리(처치/수확/제련)하는가",
  "collect":   "어떻게 담는가",
  "target":    "대상 몹/작물",
  "dimension": "overworld | nether | end",
  "scale":     {"치수 파라미터": "선택"}
}
```

사용 가능한 값 전체는 `python3 -m engine.cli vocab` 으로 확인한다.

### 예시: "크리퍼 팜"을 봤다
> 어두운 데서 크리퍼가 스폰하고, 물로 밀어서, 떨어뜨려 죽인 다음, 호퍼로 받는다.

```bash
python3 -m engine.cli principle --json '{
  "source":"natural_spawn","target":"creeper","transport":"water",
  "process":"fall","collect":"hopper",
  "scale":{"platform":15,"layers":5,"spacing":3}
}'
```

엔진이 알아서:
- 크리퍼 체력 20 → **낙하 23블록** 계산
- 오버월드 자연 스폰 → `mob_platform_tower` 선택
- 물길에 8칸마다 수원 배치
- AFK 지점을 스폰층 위 24블록으로 지정
- "스폰 청크가 1.21.9에서 삭제됨" 경고 첨부

---

## 2단계: 엔진이 모순을 먼저 잡는다

원리가 물리적으로 불가능하면 **설계도를 그리기 전에** 경고한다.

| 입력한 원리 | 엔진의 지적 |
|---|---|
| 네더 + 물 이송 | "네더에서는 물이 즉시 증발한다 → piston/gravity/mob_ai 로 바꿔라" |
| 블레이즈 + 낙하 처치 | "블레이즈는 낙하 데미지가 통하지 않는다 → lava 또는 manual" |
| 구조물 한정 스폰 | "구조물 경계 밖에 지으면 스폰이 0이다. 좌표부터 확정하라" |
| 수거 없음 | "아이템이 5분 뒤 소멸한다" |
| 낙하 높이 부족 | "데미지 N이 체력 M보다 낮다 → 즉사 안 됨" |

**이게 이 도구의 핵심 가치다.** 설계도를 예쁘게 그리는 것보다,
지어놓고 안 도는 이유를 미리 알려주는 게 훨씬 중요하다.

## 3단계: 카탈로그에서 검증된 원형을 찾는다

새로 만들기 전에 100개 중에 이미 있는지 본다.

```bash
python3 -m engine.cli list --q 철          # 이름/원리로 검색
python3 -m engine.cli list --cat nether    # 분류별
python3 -m engine.cli list --max-diff 2    # 초반에 지을 수 있는 것만
python3 -m engine.cli list --at-risk       # 재검증이 필요한 것만
python3 -m engine.cli show iron_farm       # 요약
python3 -m engine.cli design iron_farm     # 설계도 전문
```

## 4단계: 새 원리를 만나면 아키타입을 추가한다

기존 12개 아키타입으로 안 되는 **정말 새로운 원리**를 만났을 때만 코드를 건드린다.

1. `engine/archetypes.py` 에 함수 하나 추가 → `ARCHETYPES` 에 등록
2. `engine/principle.py` 의 `resolve()` 에 선택 규칙 한 줄 추가
3. `data/farms_src.py` 에 항목 추가
4. `python3 tools/build_catalog.py && python3 -m unittest discover -s tests`

전용 복셀 설계가 아직 없는 원리는 `composite` 아키타입이 **모듈 구성도**를 대신 낸다.
가짜 설계도를 그리는 것보다 "이 칸은 직접 정하라"고 말하는 게 정확하다.

## 5단계: 지어보기 전에 반드시

생성된 설계도의 **8번 점검표**를 크리에이티브에서 먼저 확인한다.
특히 이 둘은 팜이 안 도는 원인의 대부분이다:

- 주변 128블록 경쟁 스폰 차단
- 청크 로딩 (AFK 또는 `/forceload`)
